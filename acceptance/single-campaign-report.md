# BL-011 · Ручной offline-прогон на Titanic

21.11.2026, BananLoop `559621dfa0e9e230b3dd5257399b6baa88bfbade`, Python 3.12. Исторический SHA `5036a1b5498ca36ae6c445de11303b774a94e88a` присутствует в истории текущего checkout. Этот прогон относится только к текущему SHA.

Открытый датасет OpenML Titanic 40945 из репозитория подготовлен с seed 2026. Цель — улучшить accuracy прогноза выживания. Исходный вариант всегда предсказывает отрицательный класс. Локальный command-агент по сценарию предложил и реализовал правило на основе пола пассажира. Evaluator запускался локально и вычислял настоящую accuracy на зафиксированных наборах DEV, VALIDATION и HOLDOUT. Модели и сеть в кампании не использовались.

| Сценарий | DEV | VALIDATION | Финальный HOLDOUT | Решение |
| --- | --- | --- | --- | --- |
| Минимальное улучшение 0,01 | 61,73% → 77,55% | 61,83% → 70,23% | 78,57% | Кандидат принят |
| Минимальное улучшение 0,40 | 61,73% → 77,55% | Кандидат не дошёл до проверки | 61,73% | Кандидат отклонён. Сохранён исходный вариант |

Оба прогона завершились в состоянии `STOPPED / BUDGET_EXHAUSTED` при бюджете в один эксперимент. В принятом прогоне целевая точность 75% на VALIDATION не достигнута. В первом пробном запуске CLI отклонил ответ локального агента без обязательного `mechanism_key`. После исправления временного сценария выполнены два прогона из таблицы.

Команды продукта — `bananloop init`, `bananloop run`, `bananloop status --json` и `bananloop report`. Временный сценарий запуска находится в `/tmp/bananloop-bl011-titanic.py`. Каталог `/tmp/bl011-titanic-tp50bhpc/` содержит Markdown и JSON отчёты, stdout/stderr, две базы `campaign.sqlite3` с событиями и отдельные рабочие каталоги. Эти файлы доступны на машине запуска до очистки `/tmp`.

Подтверждены вычисление метрик, принятие и отклонение кандидата и генерация отчёта на реальных данных в legacy CLI. **BL-011 остаётся открытой.** Прогон не подтверждает единый пользовательский путь v2 от Goal до финального отчёта. Существующий интеграционный сценарий v2 связывает Exploration и Optimization через отдельные CLI- и API-вызовы, включая подтверждение и создание дочерней кампании. Он не использовался для приведённых выше результатов.
