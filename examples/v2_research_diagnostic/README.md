# RPDI-13R: one-command offline v2 Exploration smoke

This diagnostic creates an entirely new local Git repository, managed v2
campaign state, frozen Full Exploration spec, two research nodes and two
mock-model turns. Both jobs use the real GraphRepository, scheduler, durable
queue, pinned roles, ToolGateway, evidence publication and Research Ledger.
The second invocation must see public, unverified research memory generated by
the first. Nothing calls Codex or a remote provider.

On Manjaro/Linux, from the BananLoop repository root:

```bash
python -m pip install -e '.[test]'
python examples/v2_research_diagnostic/run_offline.py --work-dir /tmp/bananloop-rpdi13r-owner
python -m pytest tests/test_v2_research_runtime.py tests/test_exploration_adapter.py -q
```

Choose a **new/empty** `--work-dir` on every run. Generated files and state
stay inside that directory. Nothing is imported from the user's old v1 state.
Expected status: `OFFLINE_V2_EXPLORATION_PASS`, with two evidence counts
and `second_turn_received_public_memory=true`.

This is **not** a real LLM call or an official v0.2 Full qualification. The
Optimization, verified evaluation and owner-approved live Codex broker path
remain separately gated under [RPDI-13R](../../docs/rpdi/rpdi-13r-v2-runtime-integration.md).
Do not pass private gold, evaluator, auth state or original secrets to the
test agent's task tree.
