# Issue #33 security review

Date: 2026-10-10
Reviewed base: `61d427c3fe50dfef76bce36f437d4e5559757640`; scope also includes the current transfer-diagnostics diff and bounded M5 A/B evidence.

## Trust boundaries reviewed

- Bootstrap agent declarations remain untrusted. `DIAGNOSTIC_ONLY` and `UNAVAILABLE` do not elevate evaluator trust.
- Reference trust requires all three explicit operator inputs: a manifest, its exact-byte SHA-256 digest, and an approver identity. Core rejects digest, protocol, case/input identity, baseline-value, and smoke-value mismatches.
- The candidate workspace does not receive the reference manifest. BananLoop stores its frozen bytes and the verification/readiness receipts under campaign state. Reports validate the manifest digest, self-hashed verification receipt, and readiness receipt hash; missing or altered sidecars force report trust to `UNVERIFIED`.
- Reference verification is scoped to DEV. It cannot establish validation/holdout trust, and a campaign with an unverified holdout remains `DEV_ONLY`.
- Replay remains restricted to DEV/bootstrap smoke, uses a disposable workspace, and does not mutate campaign science state. Hidden validation/holdout data remains outside agent-facing planning and replay.
- Model-role receipts must describe settings actually selected by a model-aware adapter. The reviewed diff rejects model/provider/reasoning metadata on deterministic command backends, preventing those profiles from being recorded as if the adapter had applied them. Codex role dispatch builds its argv from the selected role config; a local deterministic fixture verifies strong/high vs fast/low arguments without an external model call.
- Four authorized repeated-profile Pi Cloud attempts exposed the same candidate-transfer error: `git apply` rejected the agent-workspace diff before any candidate evaluation. The first handling allowed its `ProcessError` to escape and left the campaign marked `RUNNING`; the current fix converts Git process failures in `apply_agent_changes` to `WorkspaceError`, and the engine now records `CANDIDATE_TRANSFER_FAILED`, categorizes the experiment as `CANDIDATE_NOT_MATERIALIZED` / `INFRA_FAILED`, pauses the campaign, and preserves the champion. Follow-up diagnosis reproduced the same header error with global `diff.noprefix=true`; canonical generation now also forces `a/` and `b/` prefixes, and a regression verifies safe transfer under that config. This matches the observed signature but cannot identify the old runs' exact environment because their patch bodies and effective Git config were not retained. No candidate was promoted.

## Findings and limits

No new exploitable security issue was found in the reviewed change. The operator identity is a recorded CLI assertion, not an externally authenticated signature; this contract proves pinning and consistency with measured inputs, not that the named person is authorized or that their labels are semantically correct. Campaign state is local to the operator account and is not protected against a hostile process with arbitrary filesystem access.

Follow-up transfer fix: the generated candidate patch is written as bytes to a uniquely named temporary file inside the isolated agent workspace, then applied with `git apply --binary`. The file is unlinked in a `finally` block and the containing agent workspace is removed after transfer. It is not added to the candidate diff, evaluator inputs, receipts, or trace export. Regression coverage includes binary and text changes plus global `diff.noprefix=true`. CI on commit `4351f7f` passed all four jobs, including Windows 3.12 (`270 passed`). Four Pi A1/A2/B1/B2 reruns then showed that agent-side Python verification creates `__pycache__/slug.cpython-313.pyc`, which the scope guard correctly rejected as out-of-scope. The current local follow-up removes only untracked bytecode/cache artifacts from the disposable agent workspace before patch staging, while preserving bytecode that exists in the supervisor-owned baseline. Four focused Windows regressions pass; full-suite/CI for this last change is pending.

An integration test verifies successful receipt persistence and report linkage; a tamper test confirms trust downgrade. E0–E3 campaign evidence remains unverified until an actual operator-approved manifest is used. A historical E4 GPU run exists, but no current-head run or semantic/safety/human quality review is claimed; AnimeDiff was not accessed during this implementation.
