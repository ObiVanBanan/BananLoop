## Pi role-profile pilot (2026-10-10)

The operator-authorized cloud Pi allowance was capped at four BananLoop agent actions. Two expert-init E1 campaigns used the same disposable source commit `83c5f38357a28d6f211d2d27b1fbdb2a9fe0b498` and evaluator fingerprint `ef3af235ae81b8b00f8da8895ff745d0818805c6547c2229bff5126f0f34ed3f`, with two agent actions per arm. Arm A configured `deepseek-v4-pro:0813` / high for all roles; Arm B configured the same strong model for proposer/analyzer and `glm-5.3-flash` / low for implementer. Only propose and implement were invoked; bootstrap was operator-authored through expert init, and neither run reached analyze.

- **A:** proposer returned a valid hypothesis. Implementer returned `verification_notes` as a JSON list, while `ImplementResult` requires a string. Core stopped `PAUSED_INFRA`; no candidate snapshot was produced. Two agent actions were consumed.
- **B:** proposer and fast implementer completed; candidate snapshot `02347407ec2ce794b0711fdfb90193f729e84043` changed only `slug.py`. The recorded DEV result was 0/1 and core rejected it, leaving the baseline champion unchanged. Replay under the same pre-fix runtime reproduced 0/1. Diagnosis found the fixture command used a bare `python`: on this Windows host `shutil.which()` recorded `C:\Python313\python.exe`, while `Popen(["python", ...])` actually selected a uv-managed Python 3.12 without `pytest`. The wrapper hid pytest's nonzero exit and emitted a valid-looking zero score. The current command evaluator now launches the resolved executable explicitly. Replaying the unchanged historical candidate after this fix returns `REPLAY_MISMATCH`, with the metric changing from 0/1 to 1/1; the campaign's original verdict is preserved.
- Pi teardown also exposed a stderr-reader race when the child pipe closed while a background thread was in `readline()`. The reader now exits quietly on a closed pipe, with regression coverage.

This is a **diagnostic, one-trial-per-arm implement-role pilot**, not a successful or statistically meaningful A/B. The result shows both protocol nonconformance (A) and an evaluator-launch defect corrected after B (the post-fix replay detects the changed result). The four-call allowance is exhausted; no more model calls were made. Trust remains `UNVERIFIED` without an operator-approved reference manifest, and M5 still needs multiple seeds/repeats and full campaign-role execution.

An M5 implementation audit found that a deterministic `command` backend could be configured with model/provider/reasoning metadata that its argv never applied, while the launch receipt still reported that metadata. `AgentConfig` now rejects such unapplied settings for command backends and command role overrides. The role-dispatch regression now runs the actual Codex adapter selection and `_argv()` builder for strong/high and fast/low roles, while delegating task execution to the local deterministic fixture; it checks the constructed per-role model and reasoning arguments, receipt stability across resume, and unknown effective-model reporting. This verifies dispatch wiring without spending additional model calls; it is not the outstanding multi-seed model A/B.
