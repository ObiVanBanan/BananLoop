# RPDI-14 blinded scoring report scaffold

`benchmarks/v02_full/report.py` builds a deterministic paired report from a frozen track manifest, a blinded score package, a signed independent scorer attestation, and a separate signed operator unblinding attestation. The package must contain every preregistered pair exactly once. Missing, failed, and excluded pairs remain visible in the report; accounting summaries that are missing, unknown, internally inconsistent, or over the frozen arm caps are retained but excluded from the paired estimate. The report records an oriented benefit delta (positive favors BananLoop for either outcome direction), wins/ties/losses, the preregistered approximate interval, and an underpowered outcome where the minimum is not met.

This is report assembly scaffolding, not a benchmark runner or an authorization to run either arm. It does not execute code, call a model, assign tasks, or establish evaluator isolation. The scorer attestation authenticates the submitted blinded score package, but this module does not independently rerun the evaluator or prove that scores correspond to output artifacts. `AccountingResult` values are currently signed package summaries; the report checks their internal consistency and caps but does not validate the underlying action receipt chain or authenticate a final receipt-chain head. Until those controls are integrated and independently reviewed, resource eligibility and scores are not sufficient evidence for a valid RPDI-14 benchmark result.

The unblinding document is intentionally separate from the blinded package and must be signed by a benchmark operator distinct from the independent scorer. The resulting report reveals arm labels; store it with the preregistration and signed evidence under access controls appropriate for the task data. No production or benchmark outcome is claimed by these files.
