# RPDI-14 blinded scoring report scaffold

`benchmarks/v02_full/report.py` builds a deterministic paired report only after `validate_run_gate` authenticates the manifest's prerequisite `GateEvidence`. The report binds the canonical gate-evidence digest, then verifies a blinded score package, a signed independent scorer attestation, and a separate signed operator unblinding attestation. The package must contain every preregistered pair exactly once. Missing, failed, and excluded pairs remain visible in the report. Available receipts and derived resource totals are retained for failed and excluded pairs too; missing receipts are marked `UNKNOWN`. Accounting summaries that are internally inconsistent, unknown, or over the frozen arm caps are retained but excluded from the paired estimate. The report records an oriented benefit delta (positive favors BananLoop for either outcome direction), wins/ties/losses, the preregistered approximate interval, and an underpowered outcome where the minimum is not met.

This is report assembly scaffolding, not a benchmark runner or an authorization to run either arm. It does not execute code, call a model, assign tasks, or establish evaluator isolation. It verifies each scored output file's pinned digest under the evidence root, with path traversal and symlinks rejected and a 16 MB limit. On platforms without descriptor-relative no-follow opens, the evidence root must be protected from changes throughout verification. The scorer attestation authenticates the submitted blinded score package, but this module does not independently rerun the evaluator or prove that scores correspond to output artifacts. For each arm pair it requires an independently signed ledger-head attestation binding the pair, arm label, action count, and final receipt digest to the frozen manifest. It recomputes accounting summaries from the hash-linked action receipts and checks chain integrity and caps against that pin. It does not authenticate the origin of each receipt or prove that the provider emitted every billable action. Until evaluator execution isolation and receipt provenance are independently reviewed and integrated with a runner, resource eligibility and scores are not sufficient evidence for a valid RPDI-14 benchmark result.

The unblinding document is intentionally separate from the blinded package and must be signed by a benchmark operator distinct from the independent scorer. The scorer attestation is restricted to the score-package and evaluator digests, so it cannot carry the unblinding map. This verifier does not establish a trusted timestamp ordering between the two signatures. The resulting report reveals arm labels; store it with the preregistration and signed evidence under access controls appropriate for the task data. No production or benchmark outcome is claimed by these files.
